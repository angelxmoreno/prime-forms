# Prime Forms — Project Overview
> Claude Code handoff document

---

## What Is This

Prime Forms is a CakePHP 5 survey and form collection platform. Forms are not hand-coded — they are generated by an AI agent from a markdown schema file. Submissions feed into a lightweight built-in CRM accessible via an authenticated admin panel.

---

## Tech Stack

- **Framework:** CakePHP 5.x (PHP 8.4+)
- **Database:** MySQL 8
- **Frontend:** Server-rendered CakePHP templates
- **Styling:** Tailwind CSS with per-form theming via CSS variables
- **Auth:** Appwrite-backed authentication bridged into CakePHP Authentication via local plugins
- **Authorization:** `UserAccess`, a reusable local authorization plugin integrated with CakePHP Authorization

---

## Core Concept: Schema-Driven Form Generation

The developer does not hand-code each submission form. Instead:

1. Copy `schemas/_template.md` and fill it out
2. Run the AI agent via Claude Code CLI:
   ```bash
   cat AGENT_PROMPT.md schemas/your-form.md | claude --print
   ```
3. Agent outputs the form definition, templates, and any registration artifacts needed by the app
4. Developer reviews the generated code and registers the form in the runtime form registry

### Agent Output Per Form

| Output | Path |
|---|---|
| Form class extending `BaseSubmissionForm` | `src/Form/{Name}Form.php` |
| View templates (2) | `templates/Forms/{name}/index.php` + `thanks.php` |
| Optional registration or route artifact | App-specific, depending on the final runtime registry approach |

No per-form table model, entity, or SQL should be generated for standard forms.

## Form Schema File

Each form is defined in a markdown file at `schemas/{slug}.md`. Key sections:

### Meta
```markdown
- slug: product-satisfaction
- title: Product Satisfaction Survey
- description: Post-purchase feedback survey
```

### Fields Table
```markdown
| name       | type     | label       | required | validation          | options              |
|------------|----------|-------------|----------|---------------------|----------------------|
| full_name  | text     | Full Name   | yes      | minLength:2         |                      |
| rating     | select   | Rating      | yes      |                     | 1|2|3|4|5            |
| feedback   | textarea | Feedback    | no       | maxLength:2000      |                      |
| consent    | checkbox | I agree     | yes      | mustBeTrue          |                      |
```

**Supported field types:** `text`, `email`, `tel`, `url`, `textarea`, `select`, `multiselect`, `radio`, `checkbox`, `date`, `number`, `hidden`

### Theme (optional)
```markdown
## Theme
- primary_color: #6366f1
- button_color: #6366f1
- font: default
```
Theme values are injected as CSS variables into the form template so surveys can match product branding.

### Success Behavior
```markdown
## Success Behavior
- redirect: /forms/product-satisfaction/thank-you
- flash_message: Thank you for your feedback!
```

## Database: Shared Form Storage

Prime Forms now uses a shared runtime registry and a shared submissions table.

### `forms`
```sql
id
slug           UNIQUE
title
description
form_class
schema_path
is_active
created
modified
```

### `submissions`
```sql
id
form_id
payload        JSON
ip_address     VARCHAR(45) NULL
user_agent     TEXT NULL
reviewed       TINYINT(1) DEFAULT 0
review_notes   TEXT NULL
created
modified
```

If a specific form later needs normalized relational storage, that can be added separately without changing the default form-generation workflow.

## Admin Panel

### Authentication
- Appwrite is the only identity provider
- Prime Forms uses four local plugins: `Appwrite`, `AppwriteUsers`, `AppwriteAuthentication`, and `UserAccess`
- CakePHP keeps its own session for the server-rendered web app after Appwrite login succeeds
- Initial login flows: email/password and Google
- New users get the `pending` local role on first login
- Verified email is required for admin access
- Login at `/admin/login`

### Roles & Permissions

| Capability | Super Admin | Manager |
|---|---|---|
| See all forms | ✅ | ❌ |
| See assigned forms only | ✅ | ✅ |
| View submissions | ✅ | ✅ (assigned forms only) |
| View contacts | ✅ | ❌ |
| Create contacts | ✅ | ❌ |
| Associate contact to submission | ✅ | ❌ |
| Manage local roles and assignments | ✅ | ❌ |
| Assign forms to managers | ✅ | ❌ |

### Admin Layout
- Sidebar with list of accessible form names from the `forms` table (filtered by role and assignments)
- Each form name links to its submissions table
- Submissions table: columns = Form, Submitted At, IP, Reviewed status
- Each row links to full submission detail view

### Admin User Operations
- Prime Forms does not treat the local `users` table as the authoritative admin directory
- Identity comes from Appwrite authentication
- Roles and permissions come from the local authorization layer
- New users are created locally on first successful login and receive the `pending` role
- `super_admin` can manage local roles and assignments
- Manager-specific form access is controlled locally through form assignments
- Local user rows are created automatically on first successful login
- Full admin-role management UI is a Phase 2 feature; Phase 1 can use a manual promotion path

### Submissions Detail View
- Displays all field values for that submission
- Super admin sees a "Create Contact" button
- If a contact is already linked, shows contact name with link

## CRM: Contacts

A lightweight contact manager built into Prime Forms. Super admin only.

### Contact Record
```
id
first_name
last_name
email         (unique — duplicate check on creation form)
phone
company
notes
created
modified
```

### Contact ↔ Submissions (pivot)
```
id
contact_id
submission_id
created
```

A contact can be linked to many submissions across many different forms.

### Creating a Contact
- From submission detail view, super admin clicks "Create Contact"
- Form pre-populates nothing (not all surveys collect contact info)
- Admin fills in manually
- On save: if email already exists, form throws a duplicate error — no silent merging

## Users Table

```
id
appwrite_user_id   (unique)
email              (unique)
display_name
last_login_at
created
modified
```

`display_name` is resolved from Appwrite `name`, then email local-part, then `User {short-id}`.

### Authorization Data
Roles, permissions, and scoped assignments are stored locally through the reusable `UserAccess` plugin.

### Form Assignments (pivot: managers ↔ forms)
```
id
user_id
form_id
created
```

A manager belongs to many forms. A form can be assigned to many managers.

## Key Conventions

- Use `$this->fetchTable()` — never `$this->loadModel()` (deprecated in CakePHP 5)
- Use `$this->Form->create($form)` in public views (Form object, not Entity)
- All agent-generated files include: `// Generated by Prime Forms Agent — do not edit manually`
- Standard generated forms extend `BaseSubmissionForm`
- Schema markdown is the build-time source of truth for form structure
- The `forms` table is the runtime source of truth for registered forms
- Tailwind via CDN for prototyping; swap to build step before production
- Per-form theme colors injected as CSS variables: `--form-primary`, `--form-button`
